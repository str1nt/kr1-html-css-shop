## История коммитов

После шестого PR и до добавления материалов защиты в main было 23 коммита,
включая шесть Merge-коммитов. Количество коммитов разработки в ветках:
№1 — 1, №2 — 2, №3 — 2, №4 — 3, №5 — 2, №6 — 2.
Два начальных коммита находятся в main до первой ветки.

Примеры реальных сообщений:

- `chore: configure ignored local files`;
- `feat: add semantic store layout and product illustrations`;
- `feat: handle dialog actions and client-side form validation`;
- `refactor: organize stylesheet sections and shared CSS variables`;
- `feat: add catalog contacts and shared multi-page navigation`;
- `style: implement flex navigation and named grid catalog layout`.

При просмотре опубликованных версий найдены и исправлены две проблемы:
кэширование старого CSS и приоритет рамки ошибочного поля при фокусе.
Они исправлены отдельными настоящими fix-коммитами main после соответствующих PR.
Ссылка Pages и материалы защиты также сохранены отдельными документирующими коммитами.
Даты и авторские поля вручную не подменялись, история ради временных меток не переписывалась.

## Ограничения проверки и ручная демонстрация

Полноценный VS Code в среде выполнения отсутствовал. Структуру проекта и
`git log --oneline --graph --all` в своём VS Code нужно показать самостоятельно.
Текстовая история и реальные скриншоты GitHub уже сохранены.

Терминальный `git push` не получил учётные данные. Файлы и настоящие коммиты
публиковались через подключённый GitHub; локальная копия синхронизировалась с ними.
PR, Files changed, Merge и настройка Pages выполнялись в веб-интерфейсе.

Локальные file://-страницы запрещены политикой браузера. Поэтому до слияния
проводились статические проверки и проверка синтаксиса, после слияния — проверка Pages
до начала следующей практической. Для обновлений при проверке использовались параметры
версии URL и CSS, чтобы отличать новую публикацию от кэша.

Браузерная среда ограничивала наблюдение после некоторых кликов навигации:
переходы проверялись явным открытием адресов из href. Прямое чтение значения hidden
и журнала консоли ограничено защитой данных среды. Присваивание скрытого товара
проверено в исходном JavaScript; видимый выбранный товар проверен в окне.
Отсутствие ошибок консоли отдельной проверкой не заявляется.

Фильтры — макет без отбора, форма — без передачи данных. Это намеренные границы задания.
Полная адаптивность, БЭМ, sitemap и Open Graph не требовались в обязательной части этих работ.
Отдельные страницы карточки товара и оформления заявки относятся к постановке будущей КР №1.
