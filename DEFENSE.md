# Как защитить TechStore

TechStore — учебная витрина электроники на HTML, CSS и базовом JavaScript.
Названия моделей и цены демонстрационные. Серверной части, оплаты и сохранения заявок нет.

## HTML и структура страниц

| Элемент | Для чего он нужен в проекте |
| --- | --- |
| `<!DOCTYPE html>` | Включает современный режим HTML |
| `html lang="ru"` | Указывает русский язык страницы |
| `head` | Содержит кодировку, описание, заголовок вкладки и подключения файлов |
| `header` | Шапка с названием магазина и меню |
| `nav` | Объединяет навигационные ссылки |
| `main` | Основное содержимое; на странице он один |
| `section` | Раздел с общей темой, например популярные товары |
| `article` | Самостоятельная карточка товара |
| `aside` | Дополнительная информация или боковая область |
| `footer` | Нижняя часть страницы |
| `dialog` | Нативное модальное окно заявки |
| `form` | Объединяет поля и кнопки формы |
| `label` | Подпись поля; `for` совпадает с `id` поля |
| `fieldset` и `legend` | Группа связанных полей и её заголовок |

`title` виден во вкладке браузера. `meta description` кратко описывает страницу.
`viewport` задаёт правила отображения на мобильном экране, но сам по себе не делает вёрстку адаптивной.
`alt` описывает изображение, если оно недоступно, и помогает пользователям экранного доступа.

`section` объединяет раздел страницы, а `article` можно понять отдельно от остальных карточек.
`div` используется как нейтральный контейнер, когда отдельного смыслового тега не требуется.

## CSS и блочная модель

Каждый элемент имеет содержимое, внутренний отступ `padding`, рамку `border` и внешний отступ `margin`.
При `content-box` указанная ширина относится только к содержимому.
При `border-box` в ширину входят содержимое, внутренние отступы и рамка. `margin` в неё не входит.

```css
* {
  box-sizing: border-box;
}
```

`body { margin: 0; }` убирает стандартный отступ браузера вокруг страницы.
Внешний файл CSS позволяет использовать одни стили на нескольких HTML-страницах.

| Свойство | Простое объяснение |
| --- | --- |
| `max-width` | Ограничивает максимальную ширину |
| `margin: 0 auto` | Центрирует блок с ограниченной шириной |
| `padding` | Даёт содержимому место внутри блока |
| `line-height` | Задаёт расстояние между строками |
| `border-radius` | Скругляет углы |
| `outline` | Рамка фокуса, которая не сдвигает соседние блоки |
| `gap` | Промежуток между элементами Flexbox или Grid |
| `margin-top: auto` | В карточке Flexbox отодвигает кнопку вниз |

Каскад выбирает итоговое правило из нескольких подходящих. Важны приоритет, специфичность и порядок правил.
Селектор класса обычно сильнее селектора тега; при равной специфичности побеждает правило ниже.
Поэтому правило для ошибочного поля стоит после правил фокуса и имеет достаточную специфичность.

## Переменные и состояния

```css
:root {
  --color-primary: #6551a5;
  --space-lg: 24px;
}
```

Это фрагмент общего блока переменных. `:root` выбирает корневой элемент `html`.
`var(--color-primary)` подставляет основной цвет. Если изменить его в одном месте,
компоненты, использующие переменную, получат новый цвет.

- `:hover` — указатель находится над элементом.
- `:focus` — элемент получил фокус.
- `:focus-visible` — фокус виден, например при переходах клавишей Tab.
- `:disabled` — поле или кнопка отключены.
- `[aria-invalid="true"]` — поле помечено как ошибочное обработчиком формы.
- `:target` — элемент является целью текущей якорной ссылки.

`aria-invalid` само по себе не проверяет данные. Проверка выполняется HTML-ограничениями и JavaScript,
а атрибут сообщает результат и позволяет оформить ошибку.

## Как работает форма

1. JavaScript находит окно, форму и кнопки в документе.
2. Для каждой кнопки назначается обработчик клика.
3. `button.dataset.product` получает название из `data-product`.
4. Название записывается в скрытое поле и видимую подпись окна.
5. `showModal()` открывает dialog. Браузер ограничивает взаимодействие с остальной страницей.
6. Событие `submit` перехватывается через `event.preventDefault()`.
7. `checkValidity()` проверяет ограничения полей.
8. При ошибке поля получают `aria-invalid`, а `reportValidity()` показывает подсказку браузера.
9. При успехе появляется учебное сообщение, `reset()` очищает форму, `close()` закрывает окно.

```js
selectedProductInput.value = button.dataset.product;
selectedProductName.textContent = button.dataset.product;
orderDialog.showModal();
```

`value` меняет значение поля, `textContent` — текст обычного элемента.
Скрытое поле хранит выбранный товар внутри формы и не требует ввода от пользователя.

```js
if (!orderForm.checkValidity()) {
  formElements.forEach((element) => {
    if (element.willValidate && !element.validity.valid) {
      element.setAttribute('aria-invalid', 'true');
    }
  });
  orderForm.reportValidity();
  return;
}
```

`willValidate` показывает, участвует ли элемент в проверке.
`return` прекращает обработчик: код успешного заполнения не выполняется.
`clearErrors()` удаляет старые отметки ошибок перед новой проверкой и открытием окна.

`required` запрещает пустое обязательное поле. `minlength="2"` задаёт минимальную длину имени.
`type="email"` проверяет базовый формат адреса, но не существование почтового ящика.
`type="tel"` сам по себе не проверяет формат телефона, поэтому используется `pattern`.
Телефон должен соответствовать формату `+7 (900) 000-00-00`.
Дата и комментарий необязательны. Согласие обязательно.
`novalidate` отключает автоматическую проверку при отправке, чтобы обработчик сам вызвал проверку и подсказки.
Реальной отправки нет из-за `preventDefault()`: наличие `method="post"` не означает, что данные отправились.

`defer` откладывает выполнение подключённого скрипта до разбора HTML.
Функция в `addEventListener` выполняется при событии, а не сразу при загрузке.

## Git и GitHub

| Понятие | Что означает |
| --- | --- |
| Git | Локальная система контроля версий |
| GitHub | Сервис для хранения репозиториев и совместной работы |
| Commit | Зафиксированный набор изменений с сообщением и родителем |
| Branch | Указатель на отдельную линию разработки |
| Pull Request | Предложение добавить изменения ветки в другую ветку |
| Merge | Объединение изменений; в этом проекте сохраняются отдельные коммиты |
| GitHub Pages | Публикация статического сайта из файлов репозитория |

`git status` показывает состояние файлов. `git add` подготавливает изменения к коммиту.
`git commit` фиксирует их локально. `git push` передаёт изменения на удалённый сервер.
`git pull` получает удалённые изменения и интегрирует их в текущую ветку.
После Merge на GitHub локальную основную ветку нужно обновить.
`.gitignore` исключает служебные и временные файлы, но не удаляет уже отслеживаемые файлы из истории.

GitHub Pages и Pull Request решают разные задачи: Pages публикует сайт, PR организует проверку и объединение кода.

## Ссылки и многостраничность

`href="catalog.html"` открывает другой файл. `href="#popular"` перемещает к элементу
с `id="popular"` на текущей странице. `href="index.html#popular"` открывает главную
и перемещает к её разделу. Имена файлов и id должны совпадать с href, включая регистр.

Хлебные крошки показывают положение страницы: «Главная / Каталог».
Текущая страница обозначена текстом, а ссылка «Главная» возвращает на главную.
`scroll-behavior: smooth` делает переход к якорю плавным, `:target` выделяет цель.

Страницы используют относительные пути, чтобы сайт работал в подпапке GitHub Pages.
Шапка и подвал скопированы в три небольших файла: шаблонизатора и серверной части нет.

## Flexbox и Grid на примерах проекта

Flexbox удобен для одной оси: строки меню или столбца элементов карточки.
Grid управляет строками и колонками одновременно: так устроена сетка товаров.

```css
.products-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: var(--space-lg);
}
```

`repeat(3, 1fr)` создаёт три равные колонки. `fr` — доля свободного пространства.
Три карточки становятся элементами этой сетки, но каждая карточка внутри использует Flexbox.

```css
.product-card .button {
  margin-top: auto;
  align-self: flex-start;
}
```

Внутри карточки `flex-direction: column` задаёт направление сверху вниз.
Автоматический верхний отступ кнопки занимает свободное место и прижимает её вниз.
`align-self` задаёт выравнивание конкретной кнопки по поперечной оси.

```css
.catalog-layout {
  max-width: var(--container-width);
  margin: 0 auto var(--space-2xl);
  display: grid;
  grid-template-columns: 260px 1fr;
  grid-template-areas: "filters products";
  gap: var(--space-lg);
}
```

Первая колонка имеет ширину 260px. Вторая получает оставшееся пространство.
`.catalog-filters` использует `grid-area: filters`, а `.catalog-products` — `grid-area: products`.
`justify-content` выравнивает элементы Flexbox по главной оси, `align-items` — по поперечной.
`flex-wrap: wrap` разрешает перенос элементов, когда они не помещаются в строку.

Фильтры — макет для изучения вёрстки. Кнопка применения отключена, чтобы не обещать
работающий отбор. Отдельной JavaScript-фильтрации в работах №1–6 нет.

## Что могут попросить объяснить в коде

1. Найти в `index.html` один `main` и объяснить отличие `section`, `article` и `aside`.
2. Показать связь ссылки `index.html#popular` с `id="popular"`.
3. Показать пару `label for="order-email"` и `input id="order-email"`.
4. Объяснить `name`, `required`, `minlength`, `pattern` и необязательные поля.
5. Найти `data-product`, скрытое поле и обработчик кнопки заказа.
6. Пройти обработчик `submit`: отмена отправки, очистка ошибок, проверка, сообщение и сброс.
7. Найти переменную в `:root` и два места её использования.
8. Показать `border-box`, разницу `padding` и `margin`, видимый фокус и ошибку поля.
9. Объяснить родительский grid-контейнер и дочерние области каталога.
10. Показать в истории отдельную ветку и Merge для каждой практической.

Не нужно запоминать весь файл. Нужно уметь найти нужный участок и объяснить его действие.

## Как открыть проект в VS Code

```bash
git clone https://github.com/str1nt/kr1-html-css-shop.git
cd kr1-html-css-shop
```

В VS Code выберите «Файл → Открыть папку» и откройте `kr1-html-css-shop`.
Для просмотра можно открыть `index.html` в обычном браузере. Установка пакетов не требуется.
Если папка уже клонирована и локальных изменений нет, обновите её через `git pull`.
Если есть свои изменения, сначала проверьте `git status` и сохраните их.

## Порядок демонстрации преподавателю

1. Открыть [репозиторий](https://github.com/str1nt/kr1-html-css-shop) и README.
2. Открыть [сайт Pages](https://str1nt.github.io/kr1-html-css-shop/), каталог и контакты.
3. Показать якоря и хлебные крошки.
4. Открыть форму, отправить пустую, проверить неверный e-mail и телефон, затем заполнить корректно.
5. Показать очистку формы, закрытие по кнопке и Esc. Объяснить, что данные никуда не передаются.
6. В DevTools посмотреть `.site-nav__list` (`flex`), `.products-grid` (`grid`) и области каталога.
7. Нажать Tab и показать фокус; показать состояние ошибки и отключённую кнопку фильтров.
8. Открыть PR №1–6, вкладку Files changed и статус Merged.
9. В терминале своего VS Code выполнить `git log --oneline --graph --all`.
10. Показать исходники и объяснить несколько участков из списка выше.

Скриншоты браузера находятся в `docs/screenshots.zip`, основные изображения — рядом с архивом.
Снимки структуры в VS Code и команды `git log` нужно сделать на своём компьютере:
полноценный VS Code в среде выполнения отсутствовал. Снимок истории GitHub и текстовый
вывод истории уже сохранены. Значение скрытого поля можно показать в своём DevTools,
выбрав товар и посмотрев `document.getElementById('selected-product').value`.
